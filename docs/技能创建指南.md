# 技能创建指南（原 skill-creator 技能，2026-08-19 移出技能目录）

> 定位：元技能——只在"创建/改造技能"时用，日常会话不触发，故不占技能触发索引。
> 使用：创建新技能或书转换时，由主会话引用本文件（或凭记忆执行其原则）。

## 核心原则

### ① 精炼为王（上下文是公共品）
- 技能与系统提示/对话历史共享上下文窗口；默认假设模型已经很聪明
- 每段信息自我拷问："这段值得它的 token 成本吗？"；优先简洁示例

### ② 自由度匹配
| 任务特点 | 自由度 | 形式 |
|:--|:--|:--|
| 文本/判断类 | 高 | 原则+启发式 |
| 结构敏感（表格/报告） | 中 | 步骤+输出模板 |
| 易碎/高风险（财务勾稽） | 低 | 强制检查清单+顺序 |

### ③ 触发词设计（frontmatter description）
- 写清"何时必用"（MUST BE USED 当……时）；覆盖用户自然表达变体 ≥3 个；避免过泛

## 本体系 4 件套格式

```
skills/<name>/
├── SKILL.md      # frontmatter + 核心框架 + 输出纪律 + 使用提示
├── cheatsheet.md # 决策表：步骤/检查项/基准/模板
├── glossary.md   # 术语表（有真实术语时）
└── patterns.md   # 重复情境模式（可选）
```

## 创建流程
1. 定义触发场景（用户何时需要？现有技能空白？）
2. 提取骨架（3-7 板块）→ 适配本体系（铁律/管线对齐，标注借鉴/上游/衔接）
3. 写输出纪律（区分已证实/待验证）→ 3 问验证（防乱编）+ 真实场景试跑
4. 登记：docs/技能状态.md + CLAUDE.md 索引；直接写入 skills/（git 跟踪）

## 书籍转换专用（书转换纪律）
预处理（OCR/章节定位）→ 提炼方案确认 → 转换 → 3 问验证 → 沉淀
SKILL.md 只放方法论（版权材料不入 repo）；每本转完更新技能状态表

## 防重复检查（2026-08-19 教训）
- 新技能内容与现有 skill/agent 是否重复？（重复 → 并入已有，不新建——参考 returns-analysis 并入 valuation-analyst）
- 是否只有极低触发率？（低触发 → 放 docs/ 参考文档，不占技能索引——参考本文件）
- 是否与某个 agent 职责 1:1？（1:1 → 直接改进 agent，不建技能——参考 deal-sourcing 冷邮件升级）
