# 融合机制 v1.0（独立执行 + 机制化融合）

> 定位：11 路独立执行（分析阶段）与四机制融合（综合阶段）的规范——融合靠规则，不靠整合者风格。
> 配套：仲裁规则（冲突）· 决策门（否决）· 铁律 3（反向观点）· 本机制（收敛检测 + 分歧保留）

## 一、两阶段架构

```
分析阶段（独立执行）：11 skill 各自跑
  每路输出：结论 + 依据 + 置信度（高/中/低）+ 执行状态（✅/🟡/⬜）
        ↓ 互不污染（框架纯度 + 可追溯）
综合阶段（机制融合）：四机制并行
  ① 仲裁规则   —— 框架结论冲突时按 11 条规则仲裁（R1-R11）
  ② 收敛检测   —— 关键结论统计框架支持数 → 收敛度（本机制新增）
  ③ 决策门     —— 5 道门逐条（元事实/死亡清单/好球/Will-B-P/反向观点）
  ④ 反向观点   —— 强制列出反对意见（≥正向）
```

## 二、收敛检测（新增机制）

**目的**：把"多框架指向同一结论"这个信号显式化——模型收敛 = 判断可信（Lollapalooza 正向叠加）。

**操作规范**：
1. 收集各框架对"每个关键结论"的独立判断（结论清单由融合层生成，如：壁垒/市场/团队/时机/估值）
2. 统计支持每个判断的框架数 → 收敛度 = 支持数 / 参与框架数
3. 输出格式：
```
关键结论：{结论描述}
  支持框架：{列出 N 个}
  分歧框架：{列出 M 个}（分歧保留机制）
  收敛度：N/11（≥6/11 = 高置信；3-5/11 = 中置信；<3/11 = 低置信，标记"单框架判断需谨慎"）
```
4. 收敛度等级映射：
   - ≥6/11：判断可信，作为综合结论主干
   - 3-5/11：判断可用，标注"中等置信——需交叉验证"
   - <3/11：单框架/少数框架判断——标注"不构成综合结论"，仅作候选假设

**防假收敛**：只有"独立执行"得出的判断才计入收敛——整合者自己的判断不计入（防自我引用）。

## 三、分歧保留（新增机制）

**目的**：防"一锅粥"——融合报告必须保留与主流结论不同的框架意见（框架同质化 = 名义多元、实际单一）。

**操作规范**：
1. 每个关键结论，强制列出"分歧框架"及其理由（哪怕只有 1 个框架不同意）
2. 分歧记录格式：
```
分歧点：{框架名} 不同意主流结论 {X}
  该框架的判断：{Y}
  理由：{依据}
  仲裁/处置：{按仲裁规则处理，或保留为风险提示}
```
3. 分歧不消除——保留在融合报告中（它们是未来证伪的种子）
4. 若 0 分歧（所有框架一致）——警惕：检查是否"整合者污染"（各框架是否真的独立执行）——异常信号，需复核

## 四、融合报告结构（综合阶段输出）

```
# 融合报告：{项目名}
一、执行矩阵（11 路独立执行的结论/依据/置信度/状态）
二、关键结论 × 收敛检测表（结论/支持/分歧/收敛度）
三、分歧保留清单（框架异议 + 处置）
四、仲裁记录（R# 触发的冲突及裁决）
五、决策门（5 道逐条 + 说明）
六、综合推理链（证据 → 收敛 → 结论）
七、反向观点栏（铁律 3 强制）
```

## 五、与 RWP 联动
- 每次融合执行后：新冲突 → 仲裁规则；新收敛发现 → 概念页；融合卡点 → 本机制版本递增
- 融合报告归档到项目目录（{项目名}/融合报告-{日期}.md）
