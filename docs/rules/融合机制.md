# 融合机制 v1.0（独立执行 + 机制化融合）

> 定位：11 路独立执行（分析阶段）与四机制融合（综合阶段）的规范——融合靠规则，不靠整合者风格。
> 配套：仲裁规则（冲突）· 决策门（否决）· 铁律 3（反向观点）· 本机制（收敛检测 + 分歧保留）

## 一、两阶段架构

```
分析阶段（独立执行）：11 skill 各自跑
  每路输出：结论 + 依据 + 置信度（高/中/低）+ 执行状态（✅/🟡/⬜）
        ↓ 互不污染（框架纯度 + 可追溯）
综合阶段（机制融合）：四机制并行
  ① 仲裁规则   —— 框架结论冲突时按 11 条规则仲裁（R1-R11）
  ② 收敛检测   —— 关键结论统计框架支持数 → 收敛度（本机制新增）
  ③ 决策门     —— 5 道门逐条（元事实/死亡清单/好球/Will-B-P/反向观点）
  ④ 反向观点   —— 强制列出反对意见（≥正向）
```

## 二、收敛检测（新增机制）

**目的**：把"多框架指向同一结论"这个信号显式化——模型收敛 = 判断可信（Lollapalooza 正向叠加）。

**操作规范**：
1. 收集各框架对"每个关键结论"的独立判断（结论清单由融合层生成，如：壁垒/市场/团队/时机/估值）
2. 统计支持每个判断的框架数 → 收敛度 = 支持数 / 参与框架数
3. 输出格式：
```
关键结论：{结论描述}
  支持框架：{列出 N 个}
  分歧框架：{列出 M 个}（分歧保留机制）
  收敛度：N/11（≥6/11 = 高置信；3-5/11 = 中置信；<3/11 = 低置信，标记"单框架判断需谨慎"）
```
4. 收敛度等级映射：
   - ≥6/11：判断可信，作为综合结论主干
   - 3-5/11：判断可用，标注"中等置信——需交叉验证"
   - <3/11：单框架/少数框架判断——标注"不构成综合结论"，仅作候选假设

**防假收敛**：只有"独立执行"得出的判断才计入收敛——整合者自己的判断不计入（防自我引用）。

## 三、分歧保留（新增机制）

**目的**：防"一锅粥"——融合报告必须保留与主流结论不同的框架意见（框架同质化 = 名义多元、实际单一）。

**操作规范**：
1. 每个关键结论，强制列出"分歧框架"及其理由（哪怕只有 1 个框架不同意）
2. 分歧记录格式：
```
分歧点：{框架名} 不同意主流结论 {X}
  该框架的判断：{Y}
  理由：{依据}
  仲裁/处置：{按仲裁规则处理，或保留为风险提示}
```
3. 分歧不消除——保留在融合报告中（它们是未来证伪的种子）
4. 若 0 分歧（所有框架一致）——警惕：检查是否"整合者污染"（各框架是否真的独立执行）——异常信号，需复核

## 四、融合报告结构（单版本——人话正文 + 末尾量化表）

**不再双版本**（专业版/人话版合并为一）：正文用大白话+原文引用（决策者读），专业内容以量化表形式放末尾附录（审计/存档用）。

```
# 融合报告：{项目名}（人话正文）
一、十一本书各自怎么看（每本一段话：事实+逻辑+原文引用）
二、关键判断（几本书不约而同说了同一句话——收敛信号）
三、分歧（唱反调的书 + 处置）
四、投不投？（五道门，人话说明）
五、怎么做好这个项目（里程碑/搭档/客户/迹象）
--- 附录 · 专业量化总表 ---
A. 框架评估量化表（17 项逐项打分 1-5 + 加权综合）
B. 决策门（5 道）
C. 关键结论收敛度
D. 仲裁记录
```

## 五、与 RWP 联动
- 每次融合执行后：新冲突 → 仲裁规则；新收敛发现 → 概念页；融合卡点 → 本机制版本递增
- 融合报告归档到项目目录（{项目名}/融合报告-{日期}.md）

## 六、语言规范（v1.1 补充——大白话 + 原文引用）

**目的**：融合报告是给"决策者本人"（而非专家同行）看的——术语堆砌会掩盖推理漏洞，人话逼着你想清楚。

**两条铁律**：
1. **大白话原则**：每个判断必须能用"跟朋友解释"的方式说一遍。术语出现时必须紧跟人话翻译（如："收敛度 6/11"→"十一本书里六本都指向同一个判断——这基本可以信了"）。写不出白话 = 自己还没想清楚。
2. **原文引用原则**：每个关键判断必须引用至少一处原书观点（书名+原话），格式：`（《守正》：'既上过庙堂，也行走过江湖'）`。引不出原文 = 判断缺乏根基，可能是整合者自己的偏好混入。

**对照表（术语 → 白话 → 原文）**：
| 术语 | 白话 | 原书引用 |
|:--|:--|:--|
| 收敛度 | 几本书不约而同指向同一个判断 | （穷查理：模型同向叠加=Lollapalooza）|
| 可复制性存疑 | 别人抄不抄得走？ | （守正："人无我有" vs "人有我优"）|
| 死亡谷 | 东西做出来了，卖不卖得出去 | （tech-transfer：样品产品化是最常见的死亡谷）|
| 次元壁 | 教授讲技术，客户讲生意，两边说不上话 | （守正：科研思维与商业思维之间存在"次元壁"）|
| 3P 测试 | 这事儿可能吗？靠谱吗？有证据吗？ | （IV：Possible → Plausible → Probable）|
| 里程碑期权 | 干成一件事，估值涨一截，双方都赚 | （venture-deals：目标回报率是谈判工具，不是折现率）|
